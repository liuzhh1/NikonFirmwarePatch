# 4K Open Gate 当前进展（2026-11-13）

**当前是已实现并通过隔离验证的控制、参数和元数据原型，尚未跑通真实4K Open Gate录像。没有新增可供上机的更新包。** 用户提供的原8K方案有实机可录制依据；新增4K路径仍需独立验收。

最新完整项目回归为151项通过、无跳过。其中93项执行AArch64机器码，19项是完整原厂/自制固件输入的构建检查；其他为预算、诊断和范围等检查。这些数量不代表录像帧数。本轮新增10项原厂调用方/组包/进度执行和1项窗口核对；11段新增核验窗口与自制基线一致。数学/校准/字符串、锁/堆/时间、复制辅助API及存储接口仍使用有界替身；会话配置、源图像载荷与存储完成通知为受控输入，尚未进行新的完整QEMU或实机录像验收。

原8K路线可继续复用的部分已进一步明确：任务先复制0xA8字节描述符，再把0x38字节NRMT描述符送入独立队列；输出消费者按最多三个包转交writer。writer的`0x40D21A5C`调用把参数字节复制进输出帧缓冲，`0x40D21B8C`随后提交存储。此前三个受控缓冲均保留2756/4128×2752几何，且复制后不受NRMT原槽再次复用影响。**这三个缓冲包含合成载荷，不是三帧有效TICO录像。**

进一步接入`0x40E99CDC`原厂生成调用方和`0x40D2042C`内部模式2组包任务，已无需手工注入“编码完成描述符”。当前配置下，6项待办时组包任务等待，第7项到达后形成三项输出；按测试调度逐步生产70次、提交22组共66个缓冲，最多7项输入待办，末尾剩4项。第61次确实复用首个NRMT槽，先前提交的参数正文与合成载荷仍一致。会话内部模式2仍由测试提供，不能据此认定真实NRAW会话、TICO或实际调度已验证。

## 已确认的模型阻塞

历史原厂N-RAW运行中，原生路径使用source2/ISP1，但实验header就绪轮询检查source0，后者为空；相关secondary模型也未按该布局启用。`raw_pipeline_video_frames`为RAW/ISP输出计数，尚不是编码帧数。现有零帧证据反映这条模型数据链路没有交付输出，不能用于否定原8K在实体机上的可录制性。本轮未重跑完整QEMU，该阻塞没有被本轮元数据工作消除。

## 需要继续解决的闭环

1. **生成器调度与文件关闭。** 调用方检查三个状态门控，但没有在生成NRMT前检查任务队列余量；满队列拒绝发生在生成后。已证明给定调度下的跨槽复用可正确交付，真实上层调度与采集缓冲所有权仍需核对。另一个受控案例在9次生产、完成首组后请求停止两次，6项尾部任务仍待处理，任务状态保持1，不能认定停止完成。这不是原固件故障证据；本轮保留未完成状态，没有伪造flush确认。NRMT/NCTG同一文件身份、真实Stop/I-O/close仍未验收。
2. **有效编码帧与真实几何。** 需要得到可解码的4K候选TICO/NEV，验证4140×2756编码范围、4128×2752有效区域、Bayer/采样方式及持续录制。当前只有参数一致性证据。
3. **用户操作与恢复。** 补齐4K i菜单、取消/回滚、模式切换/设置银行及代理码流；之后才能形成可供评审的完整功能路径。
4. **端到端验收。** 在同一WonderLantern基线下复跑原厂、原8K和4K候选，检查Record、Stop、卡中文件及关闭恢复；QEMU模型缺口和实体传感器/TICO验收分别记录。

`--experimental-nrmt-lifetime`继续保持原厂生成器和原8K回退，新增800字节代码且不增加全局状态。本轮只新增调用方/组包/进度执行检查及证据，没有新增固件钩子；全部组合MAIN仍为`f80ee74d…`，前端、录制、回放、NCTG旧阶段哈希保留，生产入口和原配方不变。
