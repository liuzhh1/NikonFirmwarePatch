# 4K Open Gate 当前进展（2026-11-13）

**当前是已实现并通过隔离验证的控制、参数和元数据原型，尚未跑通真实4K Open Gate录像。没有新增可供上机的更新包。** 用户提供的原8K方案有实机可录制依据；新增4K路径仍需独立验收。

| 环节 | 已完成的实验实现与证据 | 尚缺 |
|---|---|---|
| 菜单/前端 | 3个4K LAB主菜单行，保留3个8K OG及80个原厂行；原型曾在QEMU渲染菜单并观察到4K目标参数 | 4K i菜单、取消/恢复与设置银行完整联动；25/24p完整运行 |
| 几何/录制描述 | 目标有效区域4128×2752；物理2756、逻辑2760分开处理；共享表同步录制描述与四档候选预算 | driver14的真实半分辨率读出/Bayer行为；编码高度4140×2756仍为候选 |
| NRMT | 调用入口锁存身份；原厂生成器20+13个回调执行；生成期间换菜单时高度/裁切包保持一致 | 入口前的选择变化、与NCTG的同一文件身份关联、真实帧率/校准等元数据 |

最新完整项目回归为140项通过、无跳过。其中83项执行AArch64机器码，19项是完整原厂/自制固件输入的构建检查；其他为预算、诊断和范围等检查。这些数量不代表录像帧数。新增14项覆盖原厂队列及writer，17段原厂窗口与自制基线逐字节一致。数学/校准/字符串、锁/堆/时间、复制辅助API、图像提交和存储接口仍使用有界替身，编码完成通知与输出缓冲是合成输入，尚未进行新的完整QEMU或实机录像验收。

本轮明确了原8K路线可继续复用的部分：任务先复制0xA8字节描述符，再把0x38字节NRMT描述符送入独立队列；输出消费者按最多三个包转交writer。writer的`0x40D21A5C`调用把参数字节复制进输出帧缓冲，`0x40D21B8C`随后提交存储。本次三个受控缓冲均保留2756/4128×2752几何，且复制后不受NRMT原槽再次复用影响。**这三个缓冲包含合成载荷，不是三帧有效TICO录像。**

## 已确认的模型阻塞

历史原厂N-RAW运行中，原生路径使用source2/ISP1，但实验header就绪轮询检查source0，后者为空；相关secondary模型也未按该布局启用。`raw_pipeline_video_frames`为RAW/ISP输出计数，尚不是编码帧数。现有零帧证据反映这条模型数据链路没有交付输出，不能用于否定原8K在实体机上的可录制性。本轮未重跑完整QEMU，该阻塞没有被本轮元数据工作消除。

## 需要继续解决的闭环

1. **生成器调度与文件关闭。** 现在已定位writer实际复制点；仍需证明第61次参数生成复用首槽前，原厂调度已让writer完成对应复制。满队列拒绝发生在生成后，单独依靠这个拒绝不能建立所有权保证。强制绕过调度的测试可覆盖旧包，这是生命周期要求，不是原固件损坏的证据。NRMT/NCTG同一文件身份、真实Stop/I-O/close仍未验收。
2. **有效编码帧与真实几何。** 需要得到可解码的4K候选TICO/NEV，验证4140×2756编码范围、4128×2752有效区域、Bayer/采样方式及持续录制。当前只有参数一致性证据。
3. **用户操作与恢复。** 补齐4K i菜单、取消/回滚、模式切换/设置银行及代理码流；之后才能形成可供评审的完整功能路径。
4. **端到端验收。** 在同一WonderLantern基线下复跑原厂、原8K和4K候选，检查Record、Stop、卡中文件及关闭恢复；QEMU模型缺口和实体传感器/TICO验收分别记录。

`--experimental-nrmt-lifetime`继续保持原厂生成器和原8K回退，新增800字节代码且不增加全局状态。本轮只新增队列/writer执行检查及证据，没有新增固件钩子；全部组合MAIN仍为`f80ee74d…`，前端、录制、回放、NCTG旧阶段哈希保留，生产入口和原配方不变。
