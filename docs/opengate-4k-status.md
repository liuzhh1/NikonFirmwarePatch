# 4K Open Gate 当前进展（2026-11-13）

**当前是已实现并通过隔离验证的控制、参数和元数据原型，尚未跑通真实4K Open Gate录像。没有新增可供上机的更新包。** 用户提供的原8K方案有实机可录制依据；新增4K路径仍需独立验收。

最新完整项目回归为171项通过、无跳过。其中109项执行AArch64机器码，19项是完整原厂/自制固件输入的构建检查；其他为预算、诊断和范围等检查。这些数量不代表录像帧数。本轮新增6项原厂描述/配置机器码执行、2项输入检查和1项窗口核对；10段描述与静态Record窗口和自制基线一致。新增描述函数执行无需外部API替身，快照/菜单/配置帧仍是受控输入；此前的数学/校准/字符串、锁/堆/时间、复制辅助API及存储接口替身继续保留，没有新的完整QEMU或实机录像验收。

原厂RAW描述现在给出了可核对的最低栅格需求：普通4K为17,026,816字节，配置4K OG后为20,019,584字节，增加2,992,768字节；关闭OG后，RAW和编码描述逐字节恢复。**这不是实际池容量，也不证明溢出或分配已安全。** 实际单槽容量、头部/对齐及分配是否先于几何安装仍需观察。首包前置项已单列为[实机候选包说明](opengate-4k-camera-candidate.md)，QEMU完整TICO模型不作为首包必须完成的条件。

原8K路线可继续复用的部分已进一步明确：任务先复制0xA8字节描述符，再把0x38字节NRMT描述符送入独立队列；输出消费者按最多三个包转交writer。writer的`0x40D21A5C`调用把参数字节复制进输出帧缓冲，`0x40D21B8C`随后提交存储。此前三个受控缓冲均保留2756/4128×2752几何，且复制后不受NRMT原槽再次复用影响。**这三个缓冲包含合成载荷，不是三帧有效TICO录像。**

原厂生成调用方和组包任务已无需手工注入“编码完成描述符”。先前70次控制验证跨槽复用；本轮由`0x40727A18`原厂构造器生成0x90字节会话配置，并通过原厂setter分别转交record和writer，去掉直接写内部模式的环节。输入属性类型6确实映射模式2。请求种类1/2生成保留末项标志，0/3不生成；上层真实录制会选哪种请求尚未验收。

先前“停止后剩6项”的负例在分发完输入后才切换保留模式，已经没有末项可以重复。以请求种类1从开始运行时，原厂保留并重复末项来完成三项组补齐；9项控制在7次停止推进后进入状态2，9份正文/载荷完整交付，NRMT没有重新生成。提供最终通知再执行原厂清理后，剩余补齐描述符被清空，已交付内容保持不变。这个受控结果解决了该负例的配置缺项，不能替代真实写卡或文件关闭验收。

## 已确认的模型阻塞

历史原厂N-RAW运行中，原生路径使用source2/ISP1，但实验header就绪轮询检查source0，后者为空；相关secondary模型也未按该布局启用。`raw_pipeline_video_frames`为RAW/ISP输出计数，尚不是编码帧数。现有零帧证据反映这条模型数据链路没有交付输出，不能用于否定原8K在实体机上的可录制性。本轮未重跑完整QEMU，该阻塞没有被本轮元数据工作消除。

## 需要继续解决的闭环

1. **真实入口、分配与关闭。** Record消息的+0x38请求指针传递已静态定位，生产者及实际值未验收；保留末项需从开始配置。关联RAW缓冲指针与真实单槽容量并核对安装/分配顺序，再核对Stop/存储/close和NRMT/NCTG同一文件身份。受控4/10项输入交付3/9个缓冲的边界仍不能认定为相机丢帧。
2. **首包支持范围与恢复。** 有效配置退出和原8K切换已通过描述检查；取消、i菜单和设置银行完整联动尚未验收。可先收敛支持范围，但要在首包中明确落实限制，不能只写在说明里。
3. **实验打包与独立校验。** 当前只有MAIN；新增4K更新包须有独立允许差异、组件和校验检查，不能放宽原生产配方。
4. **物理录像验收。** 在受限首包中检查4140×2756编码范围、4128×2752有效区域、Bayer/采样、视角和完整解码、停止及持续录制。WonderLantern模型缺口另行记录，不能把模拟器补全等同为实机前提。

`--experimental-nrmt-lifetime`继续保持原厂生成器和原8K回退，新增800字节代码且不增加全局状态。本轮新增独立原厂缓冲核对工具、执行检查及入口证据，没有新增固件钩子；全部组合MAIN仍为`f80ee74d…`，前端、录制、回放、NCTG旧阶段哈希保留，生产入口和原配方不变。
