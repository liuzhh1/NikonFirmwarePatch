# 首个4K Open Gate实机候选包的前置项

当前尚未生成新增4K更新包。实验构建器只输出MAIN；原8K自制固件的实机录制依据不能直接转为新增4K路径的验收。

首包可以限定为FX / N-RAW / 29.97p、主菜单进入、代理关闭。**这只是建议范围，尚未在代码中完整限制或验证。** 首包不必等待QEMU完整实现TICO；传感器采样、实际画面和文件解码可以作为受限实机试验的验收项，但以下控制和内存问题须先核对。

| 前置项 | 当前证据 | 仍需完成 |
|---|---|---|

## 本轮新增的原厂缓冲描述执行

`tools/inspect_opengate4k_buffers.py`只接受已审阅的完整组合MAIN，执行原厂分类函数、RAW描述函数`0x4105C814`、编码描述函数`0x4105CA08`和现有配置插入点。快照、菜单选择和配置处CPU帧是受控输入；描述执行没有用外部API替身，也没有执行分配器、DMA、传感器、TICO或真实Record。配置仅执行至原生继续地址后恢复CPU上下文，保留RAM效果。

| 阶段 | RAW外层尺寸 | 编码尺寸 | 裁切起点 | 行步长 | 最小RAW栅格字节数 |
|---|---|---|---|---|---|
| 安装前，即使OG选择已置位 | 4140×2344 | 4140×2330 | 0,6 | 7264 | 17,026,816 |
| 安装4K OG配置后 | 4140×2756 | 4140×2756 | 0,0 | 7264 | 20,019,584 |
| 有效配置关闭OG后 | 4140×2344 | 4140×2330 | 0,6 | 7264 | 17,026,816 |

新增需求为2,992,768字节，计算为行步长×外层高度之差。这是该RAW栅格的最低跨度，不包括全部头部、其他平面或共享池需求，不是NEV压缩帧大小，也不是实际已分配容量。逻辑视图2760行另行处理。**尚无证据表明发生溢出：原厂可能预留更大的共享池。** 需要证明真实分配在正确时点取得足够空间，或据其真实协议修改分配路径。

仅置菜单标志不会安装2756行配置。无效配置快照也不会清掉已经安装的有效几何，这是原有配置入口的行为，不能据此声称取消/回滚已通过。6项机器码执行检查另覆盖三个低帧率选择、有效关闭/不支持模式恢复及4K与原8K切换；帧率检查只证明描述相同，不证明25/24p完整录制。

复跑（需Unicorn，先按实验构建说明取得完整MAIN）：

```sh
python -B tools/inspect_opengate4k_buffers.py \
  --main /path/to/opengate4k-lab-main.bi \
  --output /path/to/new-buffer-audit.json
```

工具拒绝错误长度/哈希和已有输出文件。结果及10段原厂窗口指纹见[缓冲核对记录](data/opengate4k-native-buffer-audit.json)；窗口核对不等于这些入口均已执行。

## 已定位、尚未执行的入口与池路线

Record消息组装`0x40F85618..0x40F856B8`从全局`0xA03BC2EC0+0x38`对象取得其`+8`载荷指针，放入消息`+0x38`；调用`0x40723778`尾跳到`0x407218E4`，复制消息到`0xA046130B8`并通知录制任务。任务将消息`+0x38`保存在x29，随后读取`[x29]`构造会话。上游`0x40EA0D88`另将导出请求交给异步任务；该异步生产者尚未执行和确认。

RAW描述的调用方`0x40E8DD14`先经`0x41045058`取得池节点，再调用描述函数。另一路`0x4104EC78`从配置表取得单槽大小，经`0x40CDB2C0`申请，之后通过`0x41043D28`绑定池。这条分配路线的回调使用编码描述函数，**尚不能把它等同为上述20,019,584字节RAW栅格的实际存储池**。下一步应先关联描述的缓冲指针与实际池节点/跨度，再判断是否需要补丁；不能仅根据高度增加猜测一个分配常量。
