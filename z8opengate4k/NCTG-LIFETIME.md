# NCTG 文件副本身份实验层

在原厂录制任务复制文件属性和信息块的位置锁存4K身份。复制完成后的NCTG高度、关联主图高度及RAW裁切回调使用锁存值，不再依赖当前拍摄菜单。**这是一个已识别工作副本的隔离执行验证，不代表完整停止录像或实机文件关闭已通过。** NRMT、通用writer和TICO验收仍未完成。

原厂路径及源码依据：

| 位置 | 已确认的操作 |
|---|---|
| 0x4071E208 | 将0x100字节属性复制到0xA0460BE88 |
| 0x4071E220 | 将属性指向的0x4490字节信息块复制到0xA0460EC20 |
| 0x4071E228 | 将信息块副本指针写回私有属性首字段 |
| 0x4071F3E4 | 将私有属性指针放入父描述符+0x18 |
| 0x406C12EC–0x406C1308 | 将上述源指针转交到NCTG请求+0x10并调用生成入口 |
| 0x406D243C / 0x406D2478 | 读出源指针并作为创建回调x0；x1为NCTG输出对象 |
| NCTG属性+0x20 / +0xC / +0x10 | 文件类型、尺寸代码、帧率；目标为6 / 4 / 4..6 |

NCTG的97条原生回调记录位于初始化数据的RAM地址0xA0297F658，对应MAIN加载视图0x44DEA658。高度记录位于0x44DEA9D8，创建回调0x406D2C24；RAW裁切记录位于0x44DEB298，创建回调0x406D3824。文件类型偏移还直接核对0x406D2CC0和0x406D30AC的读取与N-RAW6判断。构建前核对8段原厂窗口哈希，固定复制、字段、参数转交和回调关系。

0x4490信息块按不透明对象处理，**不推定为NRMT快照布局**，也不向原厂结构未知字段写入标记。在原始复制调用结束后，仅当源/目标/长度/属性首指针相互匹配，才登记该工作副本；N-RAW、4K低帧率、复制时OG标志、当前格式/尺寸/帧率与属性一致、已安装有效几何全部匹配才锁存target1。普通副本登记target0，其他复制使旧身份失效。原厂随后发布的私有指针还必须匹配，NCTG回调才允许覆盖。

状态使用原有复制代码区的RAM别名：ROM预留0x4096F200对应RAM0xA0FF6F200，64字节，避开D7/D8状态和16个8K代理writer槽；复用原厂文本映射后的启动复位边界清除。状态写入采用先失效、字段写入、最后发布所有者；消费者核对所有者、标记、目标和属性，并保留寄存器、NZCV与栈约定。这里仍依赖原厂工作记录的串行使用，不提供多个独立writer的并发协议。

三个NCTG入口替换前一实验录制层的4K分支。未知工作对象或普通4K属性不会因当前菜单处于OG而获得4K覆盖；8K裁切继续交回原D10，8K独立高度入口保留。代理自己的1920×1080栅格和裁切不重写，仅同步已识别副本的关联主图高度。

```sh
python tools/build_opengate4k_lab.py \
  --original /path/to/stock/Z_8_0311.bin \
  --baseline /path/to/reviewed-03.11.p0.bin --compiler /path/to/clang \
  --experimental-recorder --experimental-playback \
  --experimental-nctg-lifetime --output build/opengate4k/nctg-lifetime-003
```

必须提供`--experimental-recorder`；`--experimental-playback`可选。未启用新增开关时，前端、录制及回放阶段的旧MAIN哈希保持不变；仍只生成模拟器MAIN。

复制之前菜单已改变的情况、工作副本被下一文件替换后的旧回调，以及NRMT/其他writer的所有者关系仍待确认。这里不把NCTG锁存推定为完整关闭链路已解决。完整QEMU、TICO和实机录像仍未验收；本轮没有重跑此前9项独立模型/触点检查。精简构建和来源记录见[验证记录](../docs/data/opengate4k-nctg-lifetime-validation.json)。
