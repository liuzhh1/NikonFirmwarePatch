# 4K 文件身份回放实验层

这一层复用原8K的文件识别路线，为候选4K Open Gate补齐布局和裁切判定。它不依赖当前拍摄菜单选择，因此切回普通拍摄模式后，仍可从文件自身记录识别3:2素材。**尚未生成并解码真实4K影片；不是实机回放验收。**

| 路径 | 识别与动作 |
|---|---|
| 高光、直方图及缩略图合成器 | 原厂返回16:9类别时，按文件ID查询N-RAW记录；有效尺寸4128×2752或8256×5504才改为3:2类别 |
| type8缩略图 | 文件身份、640×360来源、无旋转、原裁切种类及3:2目标误差范围全部匹配，才解除固定水平裁切 |
| 原UI概览框 | 保留原源图条件，将484×272框内目标调整为居中408×272 |
| 原D4全屏框 | 保留原源图和矩形条件，将目标范围补齐为1024×682 |
| 动态播放 | RAW请求匹配4K有效/候选编码尺寸，或代理匹配原生RAW关联记录，再登记原D10媒体ID标记 |
| 比例应用/切换素材 | 继续使用原D10媒体ID和原生使能检查；普通素材请求通过原D10清除旧标记 |

文件记录分类只接受有效尺寸，不能把4140×2756候选编码范围当作有效文件记录。动态RAW请求另有编码范围识别入口。代理1920×1080栅格、文件字段和实际码流不在此层重写；代理是否携带预期3:2场景仍须真实文件验证。

原D10代码、文件查询和资源释放协议保留。新增类函数保持原调用方x1–x7、x12–x30和栈约定；原厂类别不是1时不查询文件。文件查询失败或信息为空时使用普通类别，并释放非空原生记录。

```sh
python tools/build_opengate4k_lab.py \
  --original /path/to/stock/Z_8_0311.bin \
  --baseline /path/to/reviewed-03.11.p0.bin --compiler /path/to/clang \
  --experimental-recorder --experimental-playback \
  --output build/opengate4k/playback-001
```

仅新增`--experimental-playback`会被参数检查拒绝。三个构建阶段均只输出模拟器MAIN；不修改生产入口、原编译配方或原组合配方。四个回放入口必须先匹配审阅D10分支，代码保留区必须为空，所有写入不得重叠；源码和机器码由独立profile固定。后续QEMU追踪可使用`--image-role opengate4k_playback`，该选项只标注实验输入身份，不改变校验。

本轮83项项目测试全部通过，无跳过。其中35项执行真实AArch64代码，11项使用完整原厂/自制固件输入构建。新增12项执行检查采用原生文件API和类别叶函数的有界桩，覆盖查询失败释放、ABI保护、当前模式无关、Q3品质位、错误文件类型/尺寸、缩略图保护条件、8K回退、RAW/代理关联、媒体ID错配和切换普通素材后的清除；新增3项完整输入检查核对D10、旧构建哈希、四个分支和全部声明写入范围。测试不包含真实文件系统、编码器或影片解码。

停止/切换模式后的录制元数据回调身份仍未验收。NRMT、NCTG和writer-close使用不同布局的上下文，尚未证实对象关联，不能借用原8K的代理writer登记表推定生命周期正确。i菜单/取消、TICO编码高度、真实传感器读出、代理码流和完整QEMU/实机回放也仍待验证。精简证据见[验证记录](../docs/data/opengate4k-playback-validation.json)。
