# 4K 录制描述实验层

该层沿用原8K补丁的录制描述同步方法，默认关闭，只生成模拟器MAIN。编码高度2756是实验候选，尚未通过TICO解码或实机录制；没有新增相机更新包。

“钩子”是原固件执行中的插入点：先执行新增的小段参数处理，再返回原厂流程。这里继续使用原厂编码和文件处理代码。

本轮实现：

- 在原RAW/Q3共有表查询入口同时提供候选录制描述及剩余时间预算。按原厂传入的表和索引判断目标，不依赖晚于内存分配阶段才安装的取景状态。
- 将Video/FX/readout8/N-RAW快照的NRMT编码高度与有效裁切高度同步为候选2756/2752。
- 对4K独立NCTG分支接入有效高度和代理关联主图高度；RAW裁切回调写入4K候选范围，代理1920×1080栅格不改。
- 私有表仅修改common6条、Fine3条、Basic3条目标记录。原8K代码、原表和未选择的记录保持原值；普通模式、代理及8K执行回退检查。

4K的NCTG高度入口是`0x406D2C8C`，8K入口是`0x406D2C9C`；代理关联主图高度入口分别是`0x406D3138`与`0x406D3150`。入口不同，不能直接复制钩子地址。原8K分支保留。

| 项目 | 候选值或状态 |
|---|---|
| 有效图像 | 4128×2752 |
| 编码描述 | 4140×2756，未通过TICO验收 |
| 物理高度 / 逻辑高度 | 2756 / 2760，分别处理 |
| 新代码 | `0x40966000`，1368字节 |
| 私有common/Fine/Basic表 | `0x4096B000` / `0x4096B400` / `0x4096B800` |
| 原8K、前端、生产配方 | 保留；默认前端MAIN哈希不变 |

预算按原厂4K High3.0/Normal1.5 bit/像素与原始预算估计固定开销，再投影到候选编码范围；Fine2.0、Basic1.0 bit/像素，使用精确分数帧率，向上取整至1Mbps。以下为预算候选，不是实测码率：

| 标称帧率 | High Mbps | Fine Mbps | Normal Mbps | Basic Mbps |
|---|---:|---:|---:|---:|
| 30p（30000/1001） | 1061 | 719 | 548 | 377 |
| 25p（25000/1000） | 893 | 607 | 465 | 322 |
| 24p（24000/1001） | 855 | 582 | 445 | 308 |

构建必须提供完整原厂C3.11及审阅的03.11.p0四功能基线，原输入身份和配方校验不变：

```sh
python tools/build_opengate4k_lab.py \
  --original /path/to/stock/Z_8_0311.bin \
  --baseline /path/to/reviewed-03.11.p0.bin --compiler /path/to/clang \
  --experimental-recorder --output build/opengate4k/recorder-001
```

不加`--experimental-recorder`仍生成原前端实验MAIN。新增汇编源码、机器码和几何由`recorder-profile.json`固定，代码、分支或保留区不匹配时拒绝构建。

本轮68项项目测试重新通过，包含23项真实AArch64执行、8项真实输入集成，以及预算、模式排除与字节范围检查。源码和完整MAIN重建哈希与维护清理前一致。

验证继续以`WonderLantern/z8-qemu@d50b07dbaeebae45b2cff936e5bfcd85251ac1fd`为基线。维护清理前曾观察原8K固件的设置阶段在selector15=0时出现CAPTG异常；该阶段actual8/driver14是取景，不是8K主录制驱动。完整原始日志未保留，后续8K与候选MAIN的完整运行对照仍需复跑，不能将此前启动的运行当作已通过。

后续新增可单独启用的[文件身份回放实验层](PLAYBACK.md)，处理布局和裁切判定；本录制层的机器码、表和MAIN哈希保持不变。仍未完成：TICO/真实传感器读出验收、文件回调在停止/切换模式后的身份生命周期、i菜单/取消、代理码流与真实影片解码。因此这一层的实现不代表4K录制功能已经完成。精简构建与验证记录见[验证记录](../docs/data/opengate4k-recorder-validation.json)。
